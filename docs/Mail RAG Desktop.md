# Mail RAG Desktop
## 画面・運用仕様 v0.3

# 1. 基本コンセプト

メールディーラーやThunderbird等に蓄積された過去のメール履歴からRAGを構築し、新しく届いた顧客メールに対する返信案をAIが生成するデスクトップアプリケーション。

通常利用時はメールシステムとの直接連携を行わない。

利用者は、

```text id="401nej"
メールソフト
   ↓
顧客メールをコピー
   ↓
Mail RAG Desktopへ貼り付け
   ↓
AI返答案生成
   ↓
コピー
   ↓
メールソフトへ貼り付け
```

というシンプルな運用を行う。

---

# 2. メイン画面構成

メニューは基本的に3つとする。

```text id="tqm6bp"
Mail RAG Desktop

├ 新規入力
├ 返答履歴
└ 設定
```

必要以上に機能を表へ出さず、RAG、Embedding、GraphRAG等は内部処理として扱う。

   ↓

   ↓

   ↓

# 9. 継続問い合わせのAI処理

2回目以降の返信生成では、最新メールだけをAIへ渡してはいけない。

必ずConversation全体を考慮する。

```text id="y6pwwc"
今回の顧客メール
       │
       ├─────────────┐
       │             │
       ▼             ▼
過去Conversation     RAG
       │             │
       │       過去の類似対応
       │             │
       └──────┬──────┘
              ↓
           Gemini
              ↓
        今回の返答案
```

Geminiへ渡すContextのイメージ：

```text id="0xsdqr"
【これまでのやり取り】

Customer:
ABC-100の電源が入りません。

Staff:
ACアダプターを接続して確認してください。

Customer:
試しましたが改善しません。
赤いランプが点滅しています。


【過去ナレッジ】

QA #102
赤ランプ点滅の場合……

QA #938
充電後も起動しない場合……


【今回の指示】

これまでのやり取りと過去ナレッジを考慮して、
今回の顧客への返信案を生成してください。
```

# 10. Conversationの要約

やり取りが非常に長くなった場合、全履歴を毎回Geminiへ送るとToken消費量が増える。

そのため、

```text id="r6f112"
最近のやり取り
+
Conversation Summary
+
RAG検索結果
```

を利用する。

例：

```text id="ot2b6d"
Conversation Summary

商品:
ABC-100

問題:
電源が入らない

確認済み:
・ACアダプター接続
・再起動

現在の状態:
赤ランプ点滅

未解決
```

このSummaryをConversationごとに更新する。

# 24. 重複インポート

同じDumpを複数回読み込んでも同一メールを重複登録しない。

判定には、

```text id="ixjfyr"
Message-ID

Mail Dealer Mail ID

本文Hash
```

などを利用する。

そのため、

```text id="ejwxpz"
1月～6月Dump
       ↓

後日

1月～7月Dump
       ↓

7月分のみ追加
```

という運用を可能にする。

# 27. 回答生成の基本ルール

AIは以下の優先順位で回答する。

```text id="g5ydmg"
1
現在のConversation

↓

2
承認済みQA

↓

3
過去の類似メール対応

↓

4
Graph Knowledge

↓

5
AI一般知識
```

原則として5は使用しない。

企業固有のメール回答では、

**過去データに根拠がないことをGeminiの一般知識だけで回答させない**

ことを基本仕様とする。

---

# 28. 信頼度不足

十分なRAG結果が存在しない場合、

```text id="arf1i6"
⚠ 十分な根拠がありません。

この問い合わせに対応する
過去の回答を確認できませんでした。
```

とする。

無理に返信文を生成しない設定をデフォルトとする。

# 29. 参考情報

これによりAI回答を人間が検証できる。
